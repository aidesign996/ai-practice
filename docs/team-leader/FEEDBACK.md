# 说说你的使用感受

[English](FEEDBACK.en.md) · [繁體中文](FEEDBACK.zh-Hant.md) · 简体中文 · [返回 Team Leader 介绍](ARTICLE.md)

欢迎使用 Team Leader，也欢迎提出疑问和建议。我会根据真实使用反馈继续优化。几句话就可以，不需要懂系统论，不需要先找到技术原因。

## 直接写就好

直接在网页文章下方留言即可，原来的反馈网页也显示同一组留言，不用按格式分栏。可以聊聊当时想做什么、实际发生了什么、怎样会更好；知道多少就写多少。觉得好用的地方，也欢迎分享。

例如：“我让负责人继续修改页面，它只回复了计划，我又追问了一次。希望它能在已有授权内继续做；确实需要我决定时，再说清卡在哪里。”

版本、使用工具或一张脱敏截图可以帮助理解，但不必为了提交反馈专门整理技术报告。欢迎用英文、繁体中文或简体中文。

[在文章下方留言](article-preview.zh.html#comments) · [在 GitHub 查看讨论](https://github.com/aidesign996/ai-practice/discussions)

三种语言共用一个公开讨论区，可以直接在文章内查看、留言和回复。首次留言需要登录 GitHub 并授权 giscus；点击发布后，内容公开保存到 GitHub Discussions。请去掉私人和业务机密信息。没有 GitHub 账号时，可以先阅读，注册后再参与。

> 我当时在做……，希望……。实际发生了……，让我……。如果能……会更好。（不知道改法也没关系。）

## 我会怎样使用这些反馈

我会和技能维护负责人整理反馈，先理解场景和原目标，再核对实际发生的事，区分当前项目的需要与值得推广的方法改进。调整后回到原场景检查，说明改变、验证结果和限制；你和其他使用者都可以在同一条讨论里继续补充。

每条建议都值得理解，但不一定需要新增通用规则或发布一个新版本。反馈的价值在于帮助方法适应真实工作。
