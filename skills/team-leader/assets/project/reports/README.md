# Decisions and Evidence

Use existing issue, report, or decision records when sufficient. Each record is a dated snapshot, with the relevant task, inputs/version, actual result, evidence entry, limits, and next action.

A short change record should make it possible to follow:
reason/request -> decision and authority -> affected product/technical contract and implementation -> verification evidence.

For design or prototype review, identify the actual artifact and consequential findings. For AI acceptance, identify the delivered version, effective criteria, observed behavior, reproducible issues, and unverified areas. Development's self-test and independent acceptance remain distinct.

Do not prescribe a row count, method recital, separate commit per role, or report per tool call. Keep raw evidence accessible without copying it into every summary. Current goal, role assignment, and acceptance state belong in [PROGRESS.md](../PROGRESS.md); unresolved/stopped topics belong in [BLOCKED.md](../BLOCKED.md).
